## Результат

- Міграція 001 і повторюваний seed створюють синтетичні програми, розділи, заходи, індикатори й деморолі. Повторний seed повертає `alreadyApplied`.
- API обмежує список, лічильники, картки та призначення областю доступу. Створення, редагування й адміністраторський імпорт записують зміни та аудит в одній транзакції.
- Координатор переглядає картки, створює й редагує заходи. Виконавець бачить призначені йому записи. При зміні розділу чи сторінки запізніла відповідь старої картки відкидається.

## Відтворення й перевірка

- Windows, Node.js `24.22.3`, npm `12.2.2`, `DEMO_MODE=true` і окрема порожня SQLite БД. Пройшли `npm ci`, `npm test` (10/10), `npm run build`, два запуски `npm run seed` і `npm start`. Seed створив 2 програми, 6 розділів, 9 демокористувачів і 4 заходи.
- У Chrome після перенесення **Координатор А** відкрив картку M-501. **Виконавець А** бачив тільки M-501, **Виконавець Б** — тільки M-502. Обом виконавцям форма створення була недоступна. [Скриншот координатора](../images/registry-demo.jpg)
- У незалежному рев’ю приватного SHA перевірено створення, редагування, версію та аудит, а також зміну фільтра, пагінацію, створення й обробку `503` із затримкою відповіді картки. Відповідь покинутої картки більше не змінює поточний екран. Автотести охопили відмову при невідповідній ролі, прострочену сесію і відкат некоректного імпорту.
