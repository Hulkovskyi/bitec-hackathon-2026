# Наскрізна перевірка

19.11.2026, Windows, Node.js 24.22.3, чисті синтетичні бази. Для первинного перенесення перевірено гілку `codex/stage-04-integrated-reporting` на базі `f2c4611`. Прийняте приватне джерело — `8119b6c`. Публічне злиття — `35f5c8d`. На локальному PostgreSQL 18 застосунок працював від ролі без прав адміністратора кластера. [PR №8](https://github.com/Hulkovskyi/bitec-hackathon-2026/pull/8)

## Як повторити

1. Клонуйте публічну `main` й виконайте команди в [README](../README.md#як-запустити). Увійдіть як **Координатор А**. У розділі 1 створіть одноразовий захід F-QA, призначте **Виконавця А**, задайте майбутній плановий строк у межах програми, напрям «Збільшення», базове 10 і цільове 100.
2. Як **Виконавець А** відкрийте F-QA й створіть результат. Вкажіть «Виконано», фактичну дату в межах програми, значення 10, короткий опис та синтетичний TXT. Подайте результат.
3. Як **Координатор А** відкрийте захід із черги **Погодження** і поверніть із коментарем. Як **Виконавець А** додайте другу версію файла, звірте доступність першої та подайте повторно.
4. Як **Координатор А** звірте цілісність нового доказу, погодьте результат і перевірте аудит. У «Сигналах» відкрийте F-QA з правила «Цілі індикатора не досягнуто». Має відкритися погоджена ревізія зі значенням 10.
5. У «Звітах» виберіть 2026 H2. F-QA має стан «Виконано», а його індикатор нижчий за ціль. Звірте рядок, підсумок, CSV і довідку. Повторіть перегляд звіту як **Керівник А**. **Виконавець Б** не повинен бачити чужий результат чи файл.

## Фактичний результат

- Повний цикл через звичайний API пройшов на SQLite й PostgreSQL. Обидві версії TXT пройшли контроль SHA‑256. Старий файл залишився доступним автору. Для іншого виконавця запити результату й файла дали `404`.
- Після погодження зафіксовано `target_not_met` і `closed_without_improvement` із посиланням на погоджений результат. Звіт координатора містив 3 рядки, з них 1 «Виконано» і 2 «Строк виконання не настав». CSV відповідав JSON, виконавець отримав `403`.
- У браузері перехід із сигналу відкрив погоджену ревізію, керівник відкрив звіт, а у виконавця була картка заходу без вкладки звітності. Завантажений H2 CSV побайтово збігся зі зразком. [Звіт у браузері](images/integrated-report-h2.jpg) · [CSV](examples/half-year-2026-H2.csv)
- У повторному локальному прогоні на чистій SQLite підтверджено `404` для чужого результату та обох версій файла, чотири послідовні переходи стану в аудиті й посилання обох сигналів на погоджену ревізію. У чистій збірці пройшли 47 тестів.
- Під час перевірки перенесення зображення й текст PDF звірено після друку фактичної розмітки й стилів збірки у фоновому Chrome 158. Зразок H2 мав одну сторінку A4 з усіма трьома розділами, трьома заходами й підсумком 1 із 3. Розширений синтетичний приклад мав три сторінки зі збереженими рядками й повтореними заголовками таблиці.

## Перевірка виправлень

За основу взято прийнятий публічний коміт `35f5c8d`. На збірці з виправленнями пройшли 48 тестів. F-QA повторено на чистих SQLite і PostgreSQL 18. Для PostgreSQL застосунок працював від облікового запису `dacm_runtime`. У H2 звіт координатора мав три заходи й один повністю виконаний. CSV збігся зі зразком з урахуванням нового UUID заходу. В обох версіях файла збіглися контрольні суми.

- У двох вкладках увійдіть як координатор. У другій перемкніться на виконавця. У першій мають змінитися роль і меню. Після виходу обидві вкладки мають показати вхід.
- У звіті, де є захід із недосягнутою ціллю, оберіть півріччя й відкрийте його з довідки. Поверніться у «Звіти» та звірте вибір. Для адаптованого Z-20 в H1 збереглися ревізія 1, дата 30.06.2026, часткове виконання і значення 78 % при цілі 100 %. [Екран H1](images/official-z20-h1.jpg) · [Походження прикладу](official-dataset-mapping.md)
- На локальному сервері з тимчасово недоступним API перевірено повторне завантаження списку користувачів, програм і картки M-501. Після завершення сесії застосунок повернувся до входу. У браузері перевірено п’ять ролей та звіт на ширинах 320 і 1280 px. У завершеній програмі кнопка додавання заходу прихована. Для нової програми на 2027 рік найраніша дозволена дата в інтерфейсі — 01.01.2027.
- Друк H1 і H2 з фактичної розмітки та стилів збірки в Chrome дав по одному аркушу A4 без додаткового вибору формату. Розширений звіт зайняв чотири сторінки. Усі 30 доданих контрольних рядків трапилися в PDF рівно по одному разу. [Оновлений зразок H2](examples/half-year-2026-H2-a4.pdf)
- На публічному демо після злиття PR №8 API підтвердив готовність бази, а координатор перемкнув H2 на H1 і відкрив три розділи та довідку. Виправлення з цього аудиту перевіряються на розгортанні після їх незалежного приймання.
