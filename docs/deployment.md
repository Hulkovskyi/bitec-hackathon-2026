# Онлайн-розгортання

[Публічний застосунок BITEC](https://bitec-hackathon-2026.vercel.app) · [Стан API](https://bitec-hackathon-2026.vercel.app/api/health)

Vercel Hobby обслуговує інтерфейс і Express API за однією HTTPS-адресою. Окремий Supabase Free зберігає записи в PostgreSQL і версії доказів у приватному сховищі. Застосунок приймає логін і пароль облікового запису, створеного адміністратором.

## Повторна публікація

З чистої копії репозиторію виконайте `npm ci`, `npm test` і `npm run build` на Node.js 24. Після приймання змін перейдіть на `main`.

Для оновлення зі збереженням чинних облікових записів застосуйте міграцію `20261120120000` до бази Production перед розгортанням. Запустіть повний SQL із файлу міграції від імені власника бази в одній транзакції, додавши `BEGIN;` перед ним і `COMMIT;` після нього. SQL додає поле керівника та записує версію міграції. [SQL міграції](../supabase/migrations/20261120120000_account_manager.sql)

Перед публікацією режиму перегляду ролей також застосуйте міграцію `20261120210000`. Вона додає таблицю, яка зберігає вибір профілю для поточної парольної сесії. [SQL міграції](../supabase/migrations/20261120210000_account_session_preview.sql)

Для розширеного адміністрування застосуйте [міграції Supabase](../supabase/migrations/) `20261120220000`, `20261120220001`, `20261120223000` та `20261120224000` перед розгортанням. Вони додають права серверній ролі `dacm_runtime` для операцій з підрозділами, профілями, ролями, заходами й каталогом програм.

Для остаточного видалення заходів та підрозділів застосуйте міграції `20261120230000`, `20261120230001` та `20261120230002`. Вони створюють чергу очищення файлів і додають необхідні права серверній ролі.

Перед розгортанням управлінських рішень та архівних сигналів застосуйте `20261120230003` і `20261120230004`. Застосунок перевіряє доступ до нових таблиць через `/api/health`.

Під’єднайте локальну папку до наявного проєкту `bitec-hackathon-2026` у Vercel, перевірте змінні Production і розгорніть застосунок.

```sh
npx vercel link --project bitec-hackathon-2026
npx vercel deploy --prod
```

Поточна публікація Vercel має власну копію збірки. Для наступних релізів джерелом є цей репозиторій. За потреби автоматичної публікації під’єднайте його в **Settings → Git** наявного проєкту Vercel після приймання коду і вкажіть `main` як Production Branch. Змінні зі службовими ключами потрібні лише в Production.

## Відтворення інфраструктури

1. Створіть окремий проєкт Supabase Free для BITEC. Виконайте `npm run create-admin` із `DACM_ADMIN_DATABASE_URL` власника бази, `SUPABASE_DB_CA` і змінними першого адміністратора. Команда застосує міграції схеми `dacm` і створить обліковий запис. Рядок підключення задайте без параметра `sslmode`, бо TLS налаштовано в коді. [Змінні першого адміністратора](../README.md#вхід-з-обліковими-записами)
2. Увімкніть вхід обмеженої ролі `dacm_runtime` з власним випадковим паролем через захищений адміністративний сеанс. Для роботи API використовуйте Transaction pooler на порту 6543 із користувачем `dacm_runtime.<project-ref>`.
3. Створіть приватний bucket `bitec-evidence`. Встановіть ліміт 4 МіБ і типи `application/pdf`, `image/png`, `image/jpeg`, `text/plain`.
4. У проєкті Vercel Hobby задайте Node.js 24 і корінь репозиторію. Параметри збірки й маршрути містить `vercel.json`. Додайте змінні до Production і розгорніть перевірений коміт.

| Змінна | Значення |
| --- | --- |
| `DACM_DATABASE_URL` | Transaction pooler URL для `dacm_runtime`. Sensitive. |
| `DACM_PUBLIC_ORIGIN` | Публічна HTTPS-адреса застосунку без кінцевого слеша. |
| `SUPABASE_DB_CA` | PEM-сертифікат із Supabase Database Settings. |
| `SUPABASE_URL` | HTTPS-адреса проєкту BITEC у Supabase. |
| `SUPABASE_SECRET_KEY` | Службовий ключ проєкту BITEC. Sensitive. |
| `SUPABASE_EVIDENCE_BUCKET` | Назва bucket. Типове значення `bitec-evidence`. |

Для підготовки навчальних записів в окремій синтетичній базі запустіть `npm run setup:hosted-demo` з `DEMO_MODE=true`, `DACM_ADMIN_DATABASE_URL` і `SUPABASE_DB_CA`. Офіційний архів BITEC можна окремо імпортувати й перевірити за допомогою скрипта `import-official-dataset.mjs`. [Імпорт і звірка H1](../README.md#локальне-демо-на-офіційному-наборі-bitec)

## Скидання облікових записів через GitHub

1. У **Settings → Secrets and variables → Actions** додайте секрети репозиторію або середовища `production`. `DACM_ADMIN_DATABASE_URL` містить рядок підключення власника цільової бази без `sslmode`, `SUPABASE_DB_CA` містить PEM-сертифікат, а `DACM_ADMIN_PASSWORD` містить пароль адміністратора від 6 символів.
2. У **Actions → Reset application accounts → Run workflow** оберіть гілку `main`, установіть прапорець, що підтверджує видалення всіх облікових записів застосунку, і запустіть процес. Він застосує решту міграцій, анулює сеанси та скине облікові записи до одного адміністратора. [Файл процесу](../.github/workflows/reset-accounts.yml)
3. Після успішного завершення увійдіть як `admin` із паролем із `DACM_ADMIN_PASSWORD`. Створіть потрібні облікові записи в **Користувачі й ролі**.

## Перевірка

Після розгортання перевірте `/api/health` і увійдіть як адміністратор. У **Користувачі й ролі → Облікові записи** створіть тестового працівника. Заповніть ПІБ, підрозділ, посаду, керівника, логін і пароль. Призначте роль і підрозділи доступу. В іншому сеансі увійдіть як цей працівник і перевірте доступ до призначеної програми та дій його ролі.

Маршрут `POST /api/auth/password` доступний за чинною парольною сесією. Він приймає JSON з полями `currentPassword` та `newPassword`. Після перевірки й заміни пароля API анулює всі сесії цього облікового запису, очищує cookie й повертає `204`. Для повторного входу використовуйте новий пароль.

Режим перегляду доступний через `GET /api/role-preview/options`, `PUT /api/role-preview` із полем `userId` та `DELETE /api/role-preview`. Почати або завершити перегляд може адміністратор із парольною сесією. Система застосовує роль і підрозділи вибраного профілю для читання та фіксує в аудиті адміністратора, який відкрив перегляд. Вийдіть із режиму перегляду, щоб продовжити зміни даних або пароля.

Через низьку активність Supabase Free може призупинити базу. Перед показом перевірте її стан та за потреби відновіть проєкт. Локальний запуск описано в [README](../README.md#як-запустити). [Відновлення Supabase](https://supabase.com/docs/guides/platform/pausing)
